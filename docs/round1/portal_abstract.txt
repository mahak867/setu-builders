Nyay Setu by Setu Builders: grievance redressal you can audit. AI proposes, rules decide, citizens confirm. A working prototype is already built and public.

Problem: portals reward closing tickets, not fixing problems. DARPG found 5.01 lakh recurring grievances on CPGRAMS. A Pune resident on the PMC Care portal: "most complaints were simply closed." Most portals are English-only forms.

Working prototype (github.com/mahak867/setu-builders), running on synthetic stand-ins for the three official datasets:
1. Intake Agent: Marathi, Hindi, English or Hinglish chat; asks for missing details (e.g. location); the citizen confirms a structured draft (category, description, location, urgency, missing details) before submission.
2. PII redaction before any LLM call; Identity-Hiding categories masked in the officer view.
3. Case Memory: top-3 similar past cases shown as evidence, never as the decision.
4. Duplicate grouping by category, location and time; every grievance keeps its own reference number.
5. SLA breach and recurrence prediction from history; escalation alert before the deadline.
6. Policy Gate: deterministic code reading the Category Master, 7 numbered rules. Sensitive cases always go to a human. An LLM (gpt-oss-120b via Groq) gives only a second opinion: disagreement can lower confidence, never approve a case.
7. Action Agent: DB update, department assignment, HMAC-signed webhooks (n8n-ready), simulated WhatsApp/email in the citizen's language.

Every AI action is logged as AI_SYSTEM (model, confidence, timestamp, reasoning, rule ID). Every grievance has a live public Langfuse trace with 9 agent spans: intake, redaction, retrieval, duplicates, SLA, LLM, policy, action.

What is different, and measured:
- Safety evaluation: 39 adversarial cases (hidden sensitive cases, prompt injection, code-mixed text) run through the real pipeline. Results: 0/15 sensitive cases auto-routed, 0/39 closed by AI, 0/8 injections succeeded, 8/8 routine cases auto-handled, 2/2 cross-language duplicates grouped. One known miss (a Marathi sentence detected as Hindi) is published, not hidden.
- AI cannot close or reject: blocked in the state machine, not by a prompt. AI can only mark "Proposed resolved"; the citizen confirms or disputes, and a dispute reopens the case automatically. The AI reopen rate is shown publicly.
- Priority = severity x urgency x affected population; duplicates raise affected population, not raw count.

Three demo scenarios already work: a routine Marathi streetlight case auto-proposed (rule AUTO-OK), a Hindi bribe complaint held for a human with identity hidden (CM-SENS), and a recurring drain complaint escalated before its SLA (ESC).
